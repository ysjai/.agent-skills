# 设计文档审核提示词

在用户要求独立审核，或设计涉及安全、权限、不可逆迁移、公共协议等高风险边界时使用。Reviewer 只读文件，只报告会影响实现计划或验收的实质问题。

```text
Task tool（优先使用宿主或项目配置的审核 subagent，未指定时使用 `explore`）：
  description: "Review spec document"
  prompt: |
    你是设计文档 reviewer。请直接读取并审核下列设计文档，不要修改文件。

    设计文档：[SPEC_FILE_PATH]
    审核范围：[FULL 或针对上轮发现的 FOCUSED_SCOPE]

    检查：
    - 目标、范围、设计和验收是否一致
    - 是否有会导致两种实现解释的歧义
    - 关键决策是否缺失，或包含未经用户确认的范围
    - 是否存在明显 YAGNI、遗漏的安全/迁移风险或不可执行验收
    - 聚焦复审时，上轮问题是否解决且没有引入相关回归

    只把会导致计划错误、实现偏离、数据/安全风险或无法验收的内容列为问题。措辞偏好和可选优化只能列为建议。

    输出：
    ## 设计文档审核
    **状态：** 通过 | 需要修改
    **问题：**
    - [path:line] [具体问题、影响和最小修正方向]
    **建议：**
    - [非阻塞建议]
```

只要列出“问题”，状态就必须是“需要修改”。修复阻塞问题后，对相关改动做一次聚焦复审；通过后才记录当前 revision 已通过独立审核。
