# 文案口径

片子是给「听」的，不是给「读」的。每一页都按这个顺序自检。

## 一页一句主张

标题写结论，不写主题。

| ❌ 主题式 | ✅ 结论式 |
|---|---|
| 需求评级方案 | 需求没有尺子，吞吐量只是一个形容词 |
| 测试提效实践 | 瓶颈不在测得慢，在用例得人手写 |
| 度量体系介绍 | 三个指标，两个陷阱 |

第二行（`<em>`）放主张里最反直觉的那半句，全篇强调色只给这里。

## 导语只做一件事

一到两句，说清「这一页要你记住什么」。不要复述标题，不要预告下一节。

## 有数字才谈口径

先看这一页有没有量化断言——百分比、倍数、样本量。金额和时长同样要带口径，但校验脚本查不到，得自己盯。没有量化断言就跳过这一节，页脚只留页码。

有的话，三选一：

- **有来源**：`.foot .fl` 写清单位、样本与出处，例如 `p50，n=8 · A 平台迭代数据`
- **没来源但数字重要**：先补一次数据；补不到就改成定性表述
- **数字不重要**：删掉，用一句话说清结论

不许用「约」「大概」「提升明显」替掉一个有来源的数字，那是拿模糊换准确。

## 说人话

- 少用「赋能 / 抓手 / 闭环 / 沉淀」这类词
- 能用动词就不用名词化：写「先量一个迭代」，不写「开展度量工作」
- 一句话超过 35 个字就拆开
- 术语第一次出现时给一句白话解释

## 结构

整份片子的骨架由类型决定，见 `deck-types.md`。这里只管单页内部的写法。

- **痛点页**：现象 → 数据 → 为什么 → 所以
- **方法页**：问题问对 → 做法 → 判据 → 边界
- **效果页**：读数 → 意味着什么 → 代价是什么
- **收尾页**：三件可执行的事，不要再来一遍总结

## 边界要主动讲

只讲成功不讲代价，听众会打折。每讲一个收益，配一句「代价是」。

## 页数与节奏

- 每 6–8 页要有一次节奏变化（深色块、图表、代码块）
- 连续三页同样版式会疲劳
- 最后一页不要放「谢谢观看」，放可执行的动作或一个问题

## 占位文案

写页面时如果某处暂时没有内容，写 `TODO：待补 XX 数据`，不要用「示例文本」糊过去——交付前搜一遍 TODO。
