# 文案口径

片子是给「听」的，不是给「读」的。每一页都按这个顺序自检。

## 一页一句主张

标题写结论，不写主题。

| ❌ 主题式 | ✅ 结论式 |
|---|---|
| 需求评级方案 | 需求没有尺子，吞吐量只是一个形容词 |
| 测试提效实践 | 瓶颈不在测得慢，在用例得人手写 |
| 度量体系介绍 | 三个指标，两个陷阱 |

第二行（`<em>`）放主张里最反直觉的那半句，全篇强调色只给这里。

## 导语只做一件事

一到两句，说清「这一页要你记住什么」。不要复述标题，不要预告下一节。

## 每个数字都要有口径

- 带单位：`29.6h` 不是 `29.6`
- 带样本：`p50，n=8`
- 带来源：`.foot` 里写清哪个系统、哪份报表
- 讲不清来源的数字，宁可不放

## 说人话

- 少用「赋能 / 抓手 / 闭环 / 沉淀」这类词
- 能用动词就不用名词化：写「先量一个迭代」，不写「开展度量工作」
- 一句话超过 35 个字就拆开
- 术语第一次出现时给一句白话解释

## 结构

- **痛点页**：现象 → 数据 → 为什么 → 所以
- **方法页**：问题问对 → 做法 → 判据 → 边界
- **效果页**：读数 → 意味着什么 → 代价是什么
- **收尾页**：三件可执行的事，不要再来一遍总结

## 边界要主动讲

只讲成功不讲代价，听众会打折。每讲一个收益，配一句「代价是」。

## 页数与节奏

- 每 6–8 页要有一次节奏变化（深色块、图表、代码块）
- 连续三页同样版式会疲劳
- 最后一页不要放「谢谢观看」，放可执行的动作或一个问题

## 占位文案

写页面时如果某处暂时没有内容，写 `TODO：待补 XX 数据`，不要用「示例文本」糊过去——交付前搜一遍 TODO。
