# 片子类型

四种类型，按「听众离场时要做什么决定」分，不按内容主题分。同样叫方案讲解，给客户的和给架构委员会的骨架不一样；决定骨架的是听众要做什么，不是讲什么。

## 怎么定类型

收料时问一句：**这份片子讲完，听众要做什么决定？**

| 听众要做的 | 类型 | 典型场景 |
|---|---|---|
| 批预算、给人、给时间 | A 方案讲解 | 客户提案、立项汇报、商务方案 |
| 拍板，或者来挑战你的技术选择 | B 方案评审 | 架构评审、技术方案讨论、ADR |
| 相信进展是真的，愿意继续支持 | C 总结汇报 | 阶段汇报、项目复盘、季度总结 |
| 带走一套能复用的做法 | D 经验分享 | 内部分享、方法论讲解、案例复盘 |

拿不准看最后一页：**你希望听众离场后立刻做什么动作**，那个动作归哪类就是哪类。

## 一眼对照

| 类型 | 页数 | 主要证据 | 收尾动作 | 全篇深色页 | 图表 | 矩阵/表格 | 每页字数 |
|---|---|---|---|---|---|---|---|
| A 方案讲解 | 8–12 | 成本对照、交付路径 | 明确要哪个决定 | 2–3 | 少 | 少 | 中 |
| B 方案评审 | 10–16 | 候选对比、失败模式 | 待决问题清单 | 1–2 | 中 | 多 | 多 |
| C 总结汇报 | 6–10 | 指标读数、偏差归因 | 下一步与所需支持 | 1–2 | 多 | 中 | 中 |
| D 经验分享 | 10–16 | 案例、反例 | 明天能试的第一件事 | 3–4 | 少 | 少 | 少–中 |

页数区间是默认值，内容是准。超了先砍可选页，不要压缩必需页。

## 偏好版式

版式本身仍由每页内容形态决定（见 `layouts.md`），这里只是每类片子的常用组合：

| 类型 | 常用版式 |
|---|---|
| A 方案讲解 | 流水线（交付路径）、左表右流程（取舍）、卡片网格、三卡 + 深色结论 |
| B 方案评审 | 左表右流程（对比矩阵）、代码面板、卡片网格（失败模式）、议程 |
| C 总结汇报 | 数字块、堆叠条形图、时间带、卡片网格 |
| D 经验分享 | 时间带（过程）、卡片网格（模式）、深色公式面板（边界）、议程 |

## A 方案讲解

听众手里有资源，你要让他现在给。

**骨架**

1. 待决问题——这一页就把要什么说清楚，一句话
2. 现状与成本——不做会付出什么：钱、时间、机会
3. 为什么是现在——时间窗口，错过会怎样
4. 方案骨架——一张图看完，不铺细节
5. 关键取舍——选了 A 不选 B，为什么
6. 交付路径——里程碑、谁负责、多久见效
7. 代价与风险——主动讲，附应对
8. 要什么支持——具体到钱、人、决策，以及什么时候要

**必需**：1、2、4、5、7、8　**可省**：3（没有真实时间窗口就别硬编）、6（内部小方案可省）

**不要出现**：技术实现细节、模块功能清单、无代价的收益列表

**自检**
- 听众离场时能复述你要的那个决定吗？
- 有没有一页明确说「不做什么」？
- 代价页是主动写的，还是等着被问？

## B 方案评审

听众会挑毛病，你要让挑战落在你准备好的地方。

**骨架**

1. 问题与约束——先说边界（预算、合规、存量系统），约束决定后面的评价维度
2. 现状与痛点——带证据，不靠形容词
3. 候选方案 A/B/C——至少两个，且都是真的能选
4. 对比矩阵——维度从约束推导，不给权重就说明理由
5. 选定与理由——明确选哪个，为什么，同时放弃了什么
6. 失败模式与降级——什么情况下会坏，坏了怎么办
7. 待决问题——还没定的、需要谁定、什么时候定

**必需**：1、3、4、5、6

**不要出现**：只有一个方案没有对比、稻草人候选、只讲优点

**自检**
- 被否掉的那两个方案，支持者会觉得公平吗？
- 失败模式有定量边界吗（不是「可能有性能问题」）？
- 待决问题写清了归属人和时间吗？

## C 总结汇报

听众已经知道你在做什么，他要判断你说的进度是不是真的。

**骨架**

1. 结论先行——三个数字或三句话，先给结果
2. 口径——这些数字怎么算的：样本、周期、取自哪个系统
3. 实际读数——目标 vs 实际，达成的和没达成的都列
4. 偏差归因——哪些是估算错、哪些是范围变、哪些是外部因素
5. 已验证 / 未验证——分清哪些站得住，哪些还要再看
6. 代价——花了多少、换来了什么、有什么副作用
7. 下一步与所需支持

**必需**：1、2、3、4

**不要出现**：过程流水账、无口径的百分比、只报喜

**自检**
- 偏差是你自己先说，还是等别人问？
- 未验证的部分标出来了吗？
- 每个数字能追溯到哪份报表？

## D 经验分享

先分两种排法，主角不同。

### D1 案例复盘（主角是项目）

1. 起点——当时是什么局面、你手上有什么
2. 转折——哪个节点出了问题，或者想通了什么
3. 关键判断——当时在几个选项里怎么选的
4. 结果——带数字，好的和坏的都说
5. 事后看——哪里做对了，哪里其实是运气

### D2 方法论讲解（主角是方法）

1. 议程——先声明要讲几块
2. 场景——一个能代入的具体局面
3. 问题——为什么原来的做法不行
4. 方法分块展开——每块按「是什么 → 判据 → 一个具体例子」讲
5. 提炼 N 个模式——抽象到能迁移走
6. 每个模式配反例——不这么做会怎样
7. 边界——什么时候不适用
8. 第一件事——明天就能做的

**两种排法共同的必需页**：踩坑、边界、第一件事。这三页最常被省，也最常被追问。

**不要出现**：只有结论没有过程、成功学叙事、无边界

**自检**
- 听众能说出「我明天可以试哪一件」吗？
- 有至少两个具体的坑吗（不是「也遇到了一些困难」）？
- 边界是主动划的，还是被问出来的？

## 混合型怎么处理

真实片子很少纯一种。规则是：**主类型定骨架，其他类型最多借一节。**

- D2 讲完方法顺手要资源 → 借用 A 的第 8 段（要什么支持）
- C 汇报里嵌一次技术复盘 → 借用 B 的第 6 段（失败模式）
- A 里插一段过往案例 → 借用 D1 的转折页

借到两节以上，说明类型选错了，重新定。

## 变体

不单列成第五类，避免分类爆炸：

- **培训** = D1 + 练习页 + 检查点。判据：每 10 分钟要有一个学员能当场验证的动作
- **路演** = A 压到 5 页：待决 → 成本 → 方案骨架 → 取舍 → 要什么
