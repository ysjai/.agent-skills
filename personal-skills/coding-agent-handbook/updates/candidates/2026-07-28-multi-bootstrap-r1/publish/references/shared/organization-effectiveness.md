# 组织效能

## 定位与事实边界

本文件面向中文工程组织，讨论受控采用 coding agent 的工程治理方法。它不构成合规意见、安全认证、供应商承诺或工具产品事实。

**事实分类：** 全文是 `experimental-guidance`。候选未登记第三方实践来源或组织内复现证据，因此不能把任何治理模式写成 `established-practice`。

## 受限试点

- **假设：** 组织能够选择低风险、可回滚、非生产的任务和明确负责人。
- **做法：** 从有限团队、有限仓库和有限任务类型开始，提前定义禁止范围、退出条件、人工审查和事件上报路径。不要把试点结果自动推广为全组织规则。
- **预期收益：** 在影响面较小的条件下发现流程、权限和培训缺口。
- **代价：** 覆盖范围有限，样本不能代表所有团队和技术栈。
- **验证方法：** 将试点前后的任务类型、失败类别、回滚次数和人工审查发现按相同口径记录；未达到预设门槛时停止扩展并复盘。

## 最小权限与敏感数据

- **假设：** 组织能识别数据分类、资产所有者和现有审批控制。
- **做法：** 按任务授予最少的文件、网络、工具和数据访问；对 MCP、Hook、插件或外部服务分别指定所有者、数据范围和撤销路径。工具资料只能说明其已覆盖范围，例如 [Codex MCP 与安全 record](../tools/codex/capabilities/mcp-and-security/records/codex-mcp-and-security-2026-07-29-r1.md) 与 [Qoder MCP 与安全 record](../tools/qoder/capabilities/mcp-and-security/records/qoder-mcp-and-security-2026-07-29-r1.md)，不能从中推导组织审批实现。
- **预期收益：** 缩小单次配置或操作失误的影响面。
- **代价：** 访问申请、审查和环境隔离可能降低短期速度。
- **验证方法：** 抽查试点配置与任务记录，确认每项额外权限有任务依据、到期或撤销方式；发现无所有者或无范围说明的连接时禁用或隔离。

## 质量与效率指标

- **假设：** 指标可以在不收集不必要个人数据的前提下定义，并能结合定性复核解释。
- **做法：** 同时观察质量和效率：例如与任务类型关联的返工、缺陷、测试/审查发现、交付周期和人工复核成本。明确基线、采样期、排除条件与数据限制，避免只用产出量评价。
- **预期收益：** 避免以单一速度指标掩盖质量或安全代价。
- **代价：** 数据收集和解释有成本，且指标可能被误读或被优化而偏离真实目标。
- **验证方法：** 在每个试点评审中比较质量、效率和安全信号；若数据口径变动或样本不足，标为不可比较而非得出趋势结论。

## 培训与治理

- **假设：** 管理者、维护者和使用者可获得与其权限相称的培训与升级路径。
- **做法：** 培训涵盖版本澄清、事实与建议区分、最小权限、审查、验证、失败报告和候选发布门禁；指定共享资产和政策的变更审批人。将工具差异作为独立主题，不用概念相似性替代证据。
- **预期收益：** 提高风险识别与升级的一致性。
- **代价：** 培训需要持续维护，并可能暴露现有流程不清晰的问题。
- **验证方法：** 用不含真实凭证的场景演练要求参与者指出版本边界、事实来源、审批路径和停止条件；根据错误类型更新培训，而不是只统计完成率。

## 扩大或停止的决策

只有在受限试点的范围、指标、权限和复盘证据都可追溯时，才讨论扩大采用。发现审批绕过、敏感数据暴露、无法解释的质量下降或没有责任人时，应停止扩展并按既有事件流程处理；本文件不授权降低任何现有安全控制。
