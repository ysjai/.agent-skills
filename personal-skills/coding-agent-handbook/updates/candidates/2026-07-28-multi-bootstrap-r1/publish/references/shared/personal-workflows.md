# 个人工作流

## 定位与事实边界

本文件面向中文工程学习者，提供跨工具的个人工程方法。除非链接到工具 record，本文件不声明任何供应商产品行为、版本、配置或支持状态。

**事实分类：** 下列流程均为 `experimental-guidance`，不是 `official-fact`、`established-practice` 或本地强制规范。本候选没有登记可复现的第三方实践来源，因而不把这些做法写成既证实的成熟实践。

## 建议流程

### 1. 澄清目标与边界

- **假设：** 任务可以用可观察的结果描述，且执行者能够向需求方确认歧义。
- **做法：** 写下目标、非目标、允许修改范围、不可接受的副作用、版本或运行环境，以及完成判据。涉及工具机制时，先链接匹配版本的工具能力索引和 record，例如 [Codex 项目指令](../tools/codex/capabilities/project-instructions/records/codex-project-instructions-2026-07-29-r1.md) 或 [Qoder Rules 与上下文](../tools/qoder/capabilities/rules-and-context/records/qoder-rules-and-context-2026-07-29-r1.md)，而不是从共享建议推导机制。
- **预期收益：** 减少范围漂移、版本误配和返工。
- **代价：** 在开始变更前需要澄清时间；紧急事项也至少要留下最小边界。
- **验证方法：** 请另一位协作者仅根据该边界复述目标、排除项和验收方式；若答案不一致，先补充说明。

### 2. 选择最小充分上下文

- **假设：** 仓库内存在能支持当前问题的说明、代码、测试或失败输出。
- **做法：** 先读任务直接相关的说明和文件，再按需扩展；把已确认事实、未确认假设和待查问题分开记录。工具问题先读版本索引和能力索引，只有适用范围相交时再读 record。
- **预期收益：** 减少无关上下文造成的误解，并让结论可追溯。
- **代价：** 初始资料不足时需要停下补证，而不能用推测填补。
- **验证方法：** 为每项关键决定标记依据路径；无法指向依据的决定应降级为待验证假设。

### 3. 分阶段执行小范围变更

- **假设：** 任务能够拆成可独立观察、可停止或可恢复的阶段。
- **做法：** 依次处理澄清、准备、变更、检查和交付；每阶段只扩大必要范围。涉及外部服务、配置、权限或生成物时，先在隔离或可恢复环境中确认副作用。
- **预期收益：** 更容易发现范围漂移和失败原因，也便于同伴接手。
- **代价：** 阶段切换会增加记录与上下文切换成本。
- **验证方法：** 每阶段保留一个可检查产物，例如确认的问题清单、最小 diff、命令输出或人工观察记录；无法验证时明确标为未验证。

### 4. 验证结果而非意图

- **假设：** 存在与变更直接相关的自动检查、可重复的手工观察或两者结合。
- **做法：** 优先运行最相关的既有检查；再检查 diff、失败输出、权限影响和未覆盖边界。不要把命令已运行、文本已生成或一次偶然成功写成已满足验收。
- **预期收益：** 将“看起来完成”转化为可复核结果。
- **代价：** 环境准备、失败分类和手工复核会消耗时间。
- **验证方法：** 将每个验收条件对应到命令、输出、观察者或明确的未执行理由；保留失败与限制，而非只记录成功。

### 5. 复盘并更新下一次的最小改进

- **假设：** 任务结束后可以安全记录过程结论，且不会泄露凭证、个人数据或内部细节。
- **做法：** 比较原目标、实际范围、验证证据和意外成本；只提炼下一次可检验的一项改进，例如补一条仓库说明或增加一个验收点。
- **预期收益：** 让学习结果可累计，而不把一次经验泛化为通用规律。
- **代价：** 需要额外时间，且结论应持续接受反例检验。
- **验证方法：** 在下一次相似任务中试用该改进，并记录是否降低返工、缺陷或澄清轮次；没有对照时保持 `experimental-guidance` 分类。

## 安全与工具资料

这些建议不授权绕过审批、沙箱、权限、网络限制或人工发布门禁。涉及 MCP 或外部连接时，分别阅读 [Codex MCP 与安全 record](../tools/codex/capabilities/mcp-and-security/records/codex-mcp-and-security-2026-07-29-r1.md) 和 [Qoder MCP 与安全 record](../tools/qoder/capabilities/mcp-and-security/records/qoder-mcp-and-security-2026-07-29-r1.md)，并以实际适用版本和组织政策为准。
